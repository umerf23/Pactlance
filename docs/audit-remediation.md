# Pactlance audit remediation and verification

Review date: 9 October 2026. Baseline: `main` commit `44e487d6711721fd16a426bb2cb893bd2ae7b47c` (tree `efc2758458925c8e0efb261d810dcc060023fc91`). The local `audit-remediation` patch is based on that exact commit. This is a code review and targeted remediation, not an independent professional security audit.

## 1. Executive summary

No practical unauthorized-fund-movement vulnerability was demonstrated in this review. Existing compiled-program tests cover sequential funding, fixed recipients, conservation, replay, reviewer authority and deadline boundaries. Confirmed defects/gaps are addressed in the patch: wallet signing omitted an explicit chain; authenticated API work lacked shared quotas; uploaded format was trusted from metadata; outbox persistence errors could be mislabeled as concurrent ownership; status and hosting documentation were stale. These fixes are **local and tested**, not already rolled out to the hosted app/database.

**Controlled devnet demo decision:** exploratory use with disposable TEST tokens is reasonable after migration/deployment smoke tests. **No-go for claiming a fully verified payment demo** until the two-wallet browser journey, alternate paths and recovery observations are recorded. **No-go for real funds/mainnet.** Human trials and browser wallet prompts cannot be proven by unit tests or this document.

## 3. Verification matrix: all handoff areas

“Confirmed” below means the stated evidence/control exists at the indicated level; it does not mean the whole system is secure.

Eligible timeout claims and execution of already authorized mutual settlements are intentionally permissionless to trigger. An outsider can pay the transaction fee, but cannot change the fixed recipients or bypass eligibility and participant authorization. The runtime tests exercise outsider callers and recipient substitution; permission to trigger settlement is not permission to withdraw funds to an arbitrary wallet.

## 4. Reproduction and regressions

- F01: baseline `StandardWalletAdapter.signTransaction` calls `solana:signTransaction` without `chain`. Run `npx vitest run tests/audit-wallet-signing.test.ts`; verify explicit chain, reject mainnet/account mismatch, changed message and dropped joint signature.
- F02: baseline authenticates users but has no shared request counter. Run `npx vitest run tests/audit-api.test.ts tests/audit-rate-limit-database.test.ts`; concurrent calls admit only configured allowance, scopes remain separate, next window resets, browser roles cannot reset/invoke quota RPC, errors fail closed. Quota transactions themselves are not rolled back by subsequent HTTP errors because each RPC call commits separately.
- F03: reserve a PDF with a correct SHA-256 for non-PDF text bytes. Baseline checks only size/hash; patch rejects before completion. Run `npx vitest run tests/phase6-api.test.ts tests/audit-evidence-type.test.ts`.
- F04: make claim-outbox insert return a storage/connection error. Baseline reports ownership; patch raises failure with no broadcast. Run `npx vitest run tests/phase7-worker.test.ts`.
- F05: baseline `/api/health` hardcodes Phase 3 and payment flags; phase documents say hosting paused. Patch returns configuration-only devnet metadata and revision, with no-store. Run `npx vitest run tests/audit-api.test.ts` and inspect aligned docs.

Read `validation-runbook.md` for exact manual steps for every remaining gate, expected/actual result fields and separate live/simulation evidence.

## 5. Remediation order and release dependencies

1. **P0, complete locally:** inspect main/CI baseline; preserve payment authority; fix explicit wallet chain without weakening exact-message/signature validation; run regression checks. Contract/IDL/program identities remain unchanged.
2. **P1, complete locally:** atomic request counters, evidence format checks, worker failure observability, deployment preflight/reporting, secret-pattern CI guard, status/docs/trust wording and live-validation worksheet.
3. **P1, external rollout pending:** review/apply `20261009094002_audit_api_limits.sql` to the matching Supabase project first; verify service-role quota call and denial to browser roles; publish patch branch/PR; require green CI on the exact patch commit; deploy after migration; smoke-test hosted Auth/projects/evidence/escrow.
4. **P1, actual evidence pending:** independent wallet journeys, failure/recovery drills, mobile/accessibility and observed participants. Any failure creates a reproducible regression before declaring a gate closed.
5. **P2, before real funds:** independent review, source-to-deployed-byte comparison, governance/custody, limited worker-fee key, monitoring/alerts, retention/deletion, dependency/service outage planning and applicable product/legal arrangements.

The migration is isolated/additive. If rollout fails, revert app code to the previous deployment; leaving counters in place is safe. Migration availability is mandatory for this patch's authenticated API; missing RPC returns 503 rather than silently disabling abuse controls. Counters contain only Auth UUID, scope, count and window, with one row per user/scope and user-delete cascade. No IPs/private evidence/secrets are stored.
